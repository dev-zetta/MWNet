# Canonical character and stat repair

Unattended character creation exposed a real server defect: ordinary race/class changes exceeded the gameplay progression bounds, so the client could show the selected stats while CoreScripts retained default values. Respawn then loaded those defaults. New characters now receive server-derived level-one attributes, skills and resource capacities from the enforced race, class and birthsign content before CoreScripts saves the character. Creation admission is private server state with a bounded stage range and one-shot completion; wire CharGen fields cannot create or reopen it. Normal progression validation remains active after completion.

The native tests cover authorized and forged creation stages, repeated completion, canonical built-in and custom classes, duplicate/invalid selections, passive starting abilities, unsupported stat-changing abilities and atomic progression bounds. Existing accounts retain their saved progression; this change does not silently rebuild older characters. The server initializes trusted inventory before requesting equipment. Only the record tables needed for creation are retained after loading content.

The same investigation found attribute/skill spell calculations reading the dynamic-only current field and resource writers storing a maximum as an additive modifier. Player spell stats now use bounded base/modifier/damage values. Player and NPC health, magicka and fatigue share a canonical writer, and capacity uses base plus modifier independently of current. Real Player/Actor packet round trips feed OpenMW's own DynamicStat implementation, including depleted health, negative fatigue and nonzero modifiers. The earlier spell-stat extraction reproduces a native regression failure; the corrected extraction passes.

All six native CTest suites passed in the local Ubuntu 24.04/Clang environment after these changes: encrypted headless integration, unit/security/mechanics, actor/player packets, canonical magic content, persistence faults and discovery. The complete log is retained at `build/automated-gameplay-builder/stat-repair-build-4.log`. These are development-source checks; clean-source package validation, the rendered creation/persistence/respawn oracle and downloadable artifact hashes remain separate release evidence.

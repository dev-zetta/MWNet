# playit integration evidence, 2026-10-28

The operator confirmed a playit Premium subscription and an online agent named `mwnet-master`; the supplied dashboard screenshot shows a connection through Sweden, Europe. This is operator-provided agent status, not an independent public-directory reachability result. No agent secret was supplied to the repository or read from the NUC during this change.

Added a separate `mwnet-playit` Compose deployment with a required external credential file, pinned official 1.0 image, host networking, restart policy, 256 MiB memory/one CPU/128 PID limits and three rotating 10 MiB logs. The optional directory overlay replaces both original Caddy host bindings with IPv4 loopback bindings and leaves port 8080 unpublished. Existing agent instructions remain compatible; adopting the pinned configuration can recreate its container and is a deliberate operator action.

The official registry was queried with `docker buildx imagetools inspect ghcr.io/playit-cloud/playit-agent:1.0`. Its multi-platform index digest is `sha256:5b7748d3e8564f1cac3d3a295a23640136fbf774c76a9509bd262d16b324b06b`, with an amd64 manifest of `sha256:33a05b36b16c2b036ab4fef951d9a7c029e91509257fb0e9fbcea2566d7883c0`. This change pins that deployed 1.0 line (1.0.12); the separately verified 1.1.0 tag adds secret-file and Docker logging changes and is not silently substituted.

The appliance builder now copies only an explicit list of optional playit templates and documentation into future payloads. It does not download/export the agent image or collect local credential files. Symlinked template inputs are rejected. Existing ISO files and the installed NUC were not rebuilt, modified or restarted by this repository change; the new guide explains copying the optional files while preserving the appliance's generated Compose file and image locks.

Validation passed: `python3 CI/test_discovery_playit.py -v` ran eight tests with Docker Compose v5.1.4's real configuration parser, including source and generated appliance overlay merging, required credential-file failure, literal secret characters, bounded agent configuration, exclusion of host secrets from packaging, symlink rejection and Git ignore rules. `python3 CI/test_discovery_appliance.py` passed 15 tests and `python3 CI/test_discovery_host_setup.py` passed 10 tests, for 33 passing tests total. Python compilation and whitespace checks also passed. Initial test assertions needed adjustment because canonical Compose JSON escapes literal dollar signs and renders memory limits as numeric strings; the final checks account for this serialization.

No local Docker daemon was available for a new container smoke test; configuration validation does not require one. Host-level setup/agent operation was previously exercised by the operator, but this exact pinned configuration, its memory allowance and public ingress remain untested in a running container here. No hostname, DNS record, HTTPS gateway, certificate issuance/renewal or public API registration was configured as part of this change.

Public acceptance still requires the chosen hostname, gateway/DNS configuration, verified TLS and renewal, a full signed challenge/update, private operational-route checks and a remote identity-pinned game probe. With PROXY protocol disabled, clients share the directory's observed-source rate bucket; individual client-IP attribution requires a restricted receiving listener and spoofing tests. Tailscale SSH remains administration only. The stable release's independent security, cross-platform, legal and beta gates remain open.

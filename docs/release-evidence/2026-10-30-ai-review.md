## Security findings and corrections

| Finding | Impact and correction | Validation |
| --- | --- | --- |
| AUTH-01: throttled account names reserved global tracking entries | Requests rejected by the per-address pre-KDF limiter still allocated account/address failure records. Rotating names from one throttled address could exhaust the shared tracking capacity and deny another address. New failure records are now allocated only after a token is available. Existing lockouts, capacity limits and expiry remain enforced. | The new bounded-capacity regression failed on the original implementation and passes after the fix. It checks unchanged tracking under rejected requests, admission from another address and admission after refill. |
| AUTH-02: server accepted the wrong content-manifest shape | The shared codec allows zero or multiple checksums because server content requirements use those forms. The server's client-manifest path nevertheless indexed the first checksum without first enforcing the client role. Empty vectors could reach an invalid access before account authentication. The server now requires a nonempty manifest, nonempty filenames and exactly one checksum per file before that path. | Actual codec round trips cover empty manifests, empty checksum vectors, multiple checksums, empty names and a valid CRC value of zero. The generic codec retains server wildcard and alternative-checksum compatibility. No remote crash probe was used. |
| DIR-01: broad JSON expanded before schema rejection | A shallow body below the existing two-MiB limit could allocate a large PropertyTree before validation rejected it. A structural pre-scan now limits containers and unquoted separators to 4,096, preserving the existing depth/body limits. | The rejection regression failed before the fix and passes afterward. Quoted/escaped punctuation and a maximum 100-envelope response remain accepted. A local native replay of the same 2,097,151-byte input dropped peak RSS from 328,228 KiB to 15,928 KiB and elapsed time from about 0.65 to 0.012 seconds. These are one-input measurements, not a concurrent abuse-capacity claim. |

## Licensing assessment and corrections

The main `LICENSE` is byte-identical to David Cernat's upstream TES3MP commit `19998f841321891f461ae3dbe681b83d42389cc0`, dated April 18, 2021 and titled `[License] Add additional terms allowed by the GPL v3`. Its complete SHA256 is `98f242648272e2e02aa9cf2d907eff760d32d6201080edb752367c57cbbc46f8`. MWNet did not author those inherited terms. Both the complete file and its TES3MP additional-terms block were compared directly with that Git object; this review leaves them unchanged and preserves OpenMW, TES3MP and dependency credits.

The AI textual assessment finds the warranty/liability clauses consistent in subject with GPLv3 section 7(a), notice/origin/name/trademark provisions with sections 7(b-e), and the clause limited to a conveyor's contractual liability assumptions with section 7(f). This is an inference from the actual clauses and [GNU's GPLv3 text](https://www.gnu.org/licenses/gpl.en.html#section7), not a ruling about enforceability or proof of every historical contributor's rights. The upstream notice identifies TES3MP source; this review does not extend it to all OpenMW code or claim MWNet can relicense upstream contributions. No particular unauthorized addition or incompatible clause was established. The practical recommendation is to retain the inherited text and attribution, record that provenance and revisit the assessment if an actual rights dispute or conflicting grant is identified.

The concrete distribution defect was missing notice delivery. All four published archives were inspected, including APFS contents of both DMGs and native loader imports. A source-oriented SBOM naming MIT/BSD or `NOASSERTION` does not deliver required copyright/license texts. The Linux packager now collects 15 exact source/font/CoreScripts and pinned fetched-dependency notice inputs, checks their hashes and runtime pins, and includes source directions and a notice manifest. Four package tests cover full client/server and server-only output, tampered notice refusal and stale-pin refusal. A separate 15-input staged archive, SHA256 `b29a6c92cb21ade68a5ac5af72ccc0d2372c446f7b934af1bf2978483baf754f`, using the unchanged alpha.3 binaries passes the new notice check; it proves packaging delivery only and is not a corrected security runtime or a replacement release.

All three actually shipped font families have companion license texts in the existing archives. No defect is claimed for RussoOne, which is absent from those archive inventories. The Linux archive does not bundle shared runtime libraries; those are supplied by the operating system and listed in `runtime-dependencies.txt`. Future Linux packages still need matching runtime/source/package evidence; the new notice collection alone is not a complete legal clearance.

Windows and macOS do bundle additional libraries, so their experimental status does not waive distribution duties. Their next packages need the exact Qt/SDK/transport/runner notice inputs and corresponding source/build material where required for FFmpeg, OpenAL Soft, libiconv, OSG/OpenThreads, Qt and macOS libintl. The exact SDK archives and recipes were recovered and hashed, but recipes are not the upstream source payloads. Runner-sourced Homebrew inputs and the macOS OpenSSL build/runtime version mismatch also need captured provenance. The mismatch is a security/provenance question, not an automatic licensing incompatibility. The unsupported macOS directory backend outside the app bundle is omitted by the corrected future desktop packaging rules because its absolute Homebrew imports were not relocated.

The [GNU GPLv3 source and notice conditions](https://www.gnu.org/licenses/gpl.en.html#section6), [FFmpeg licensing guidance](https://ffmpeg.org/legal.html) and [Qt licensing documentation](https://doc.qt.io/qt-6/licensing.html) support the delivery work above. They do not certify this distribution. Private inventories and exact SDK recipe maps are retained under `build/ecc-review/licensing/`; no copyrighted Morrowind assets or private server data are included in this report. Existing public artifacts were not silently repacked or relabelled.

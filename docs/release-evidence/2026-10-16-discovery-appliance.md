# Directory installer ISO preparation, 2026-10-16

Built a staging Ubuntu Server 24.04.5 amd64 installer ISO for the MWNet directory. The image contains the current directory and pinned Caddy containers, Docker/Compose/Tailscale/OpenSSH bootstrap, runtime configuration, source archive, integrity checks and operating instructions. Disk selection, network and account creation remain interactive. Host packages require internet access on first boot; no production credentials or hostname are embedded and public services remain stopped until configured.

The input Ubuntu ISO signature was verified with `gpgv` against `/usr/share/keyrings/ubuntu-archive-keyring.gpg`, and its SHA-256 matched the signed `SHA256SUMS`: `97f3d7ffb032c3eb3b23d2c8be9cc76e60c2c1f2c0146ba5ba9fe01cafae0fd8`. The output is `build/discovery-appliance/mwnet-directory-ubuntu-24.04-amd64.iso`, 4,144,955,392 bytes (about 3.86 GiB), SHA-256 `2329e111399ddeec1758ada7c3a57e72819b3c7ee6a3bc8c94fab88adcd21377`. The adjacent `.json` and `.iso.sha256` files contain provenance and the portable output checksum. This is a local staging artifact, not a published release.

Build inputs came from working-tree bytes of explicitly selected tracked paths at base revision `4a92d877b45a937686e38b8c3b55aab4964c9584`; their aggregate SHA-256 is `345f397f4db0db89c5f031888e259bc860f51bbd01ccda3974a43389c4734bea`. These inputs include the CMake correction excluding full-game TimedLog tests from directory-only configuration. A clean directory build had exposed a missing `Boost::filesystem` target through those tests; the corrected directory configuration built and its `mwnet-discovery` CTest passed. Application dependencies were built in the container, not installed on the workstation.

All 14 appliance safeguard tests and all seven host-bootstrap tests pass. They cover signature/checksum rejection, tracked input restrictions and credential filename rejection, interactive storage/account setup, private backend publication rules, offline image configuration, first-boot failure handling and completion markers. `bash -n` passes for both bootstrap scripts. `systemd-analyze verify` accepts the service/timer; an unrelated existing host VPN-unit deprecation warning is outside this change. The timer avoids ordering the preparation service both before multi-user startup and after cloud-init finalization.

Extracted the completed ISO and verified all 385 entries in `md5sum.txt` and all 13 payload SHA-256 entries. Original boot-image files are excluded from Ubuntu's MD5 manifest, so relocated boot metadata does not invalidate it. An initial remaster attempt stopped because xorriso preserved the read-only mode of extracted `md5sum.txt`; the builder now explicitly makes its private staging copy writable before appending new entries. Both failed and corrected build logs remain under `build/discovery-appliance/`.

Reloaded the exported archive and verified both image IDs against `images.lock`. Started the directory in a disposable container with no external network, no published ports, a read-only filesystem, dropped capabilities and bounded memory/PIDs; `/healthz` returned `{"status":"ok"}`. Removed that test container afterward. These checks establish directory runtime startup and archive integrity, not public discovery acceptance or Tailscale connectivity.

BIOS and UEFI boot entries and the hybrid MBR/GPT layout were preserved using xorriso boot replay. Both firmware modes reached Ubuntu's interactive installer language-selection screen in separate QEMU TCG VMs with 2 GiB RAM, two virtual CPUs, no hard disks and no network interfaces. Screenshots and logs are retained as `build/discovery-appliance/boot-bios.*` and `boot-uefi.*`. Both VMs were stopped through their monitors and exited successfully. These are bounded boot smoke checks; no destination disk was installed or erased.

Full installed-system first-boot provisioning, administrator SSH/Tailscale access, physical hardware and Secure Boot acceptance remain unverified. Public DNS/HTTPS and any CGNAT tunnel still require the chosen hostname and deployment environment. The independent security, cross-platform, legal and beta release gates remain open. Do not infer production or stable-release acceptance from this installer build.

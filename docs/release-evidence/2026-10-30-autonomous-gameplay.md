# Autonomous gameplay development validation

The real rendered client and encrypted dedicated server passed the strict unattended suite in development run `dev-07`: ten scenarios, 127 planned native actions, 61.324 seconds. The run used disposable loopback accounts, identity, passwords and profiles; the owned canonical game files were mounted read-only. Recordings and structured receipts remain under `build/automated-gameplay-runs/dev-07/`. No operator gameplay was required.

The checks cover normal character-creation forms, an independent native starting-stat oracle, server persistence and fresh-client reconnect, movement/inventory/door activation, the normal arrest response, incoming NPC damage without a capacity change, fist-hit confirmations and knockout/health damage, active and queued temporary effect cleanup, permanent ability/stat preservation, conversation closure on respawn, and a live two-client inventory change released only after both clients see the old contents. Wrong keys, saved-key conflicts, missing content and unsafe control inputs are rejected. Client errors, falling-into-void recovery and server gameplay violation counters fail the run.

The tests found and retained genuine failures before passing. The outbound actor/container regression and spell-stat extraction have native failing/passing evidence. The conversation regression failed after resurrection with the old client. Video review also rejected harness-only mistakes involving incomplete form teardown and a landing point behind an NPC. The strict stat comparison then caught a real permanent-ability duplication: terminal death cleanup and its caster purge removed source-owned effects, allowing birthsign bonuses to be applied again after server restoration. Connected multiplayer players now preserve those sources through both cleanup paths; ordinary NPC and single-player cleanup retains its existing policy.

All six native suites passed after the client/server changes. The canonical-content validator additionally accepted all 5,460 playable race/class/birthsign/sex combinations from the three owned ESMs; this checks derivation/admission, rather than rendering every combination. Python tests cover fixture geometry, verdict/provenance/cleanup behavior and the real Lua fixture's gating, ordering and persistence. Input-boundary validation exercises the real client without a display. The separate portable/security ASan/UBSan run passed in its explicitly recorded narrower scope.

The recorded software-rendered workload peaked at 1,169,973,248 bytes of container memory (about 1.1 GiB), under a six-CPU/12-GiB limit. That is a short test workload with up to two rendered clients and recording, rather than a sixteen-player capacity or long-soak result. Videos use null audio output; canonical sound calls and identifiers are checked, while physical audio-device acceptance remains outside this procedure.

These development artifacts were produced while implementation was uncommitted and are diagnostic evidence. Publication still requires a clean source revision, fresh platform/package checks, and the same graphical suite against the actual extracted Linux release archive with matching binary and manifest hashes. The final downloadable release validation record identifies those artifacts. Stable security, legal, cross-platform gameplay and time-based gates remain open.

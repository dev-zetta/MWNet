# Actual Mac bundle payload mapping to preserved SDKs

Offline inspection of the unchanged Apple Silicon DMG `20679685dcd60299fa43eed4f2da53008fee9ef5bf3d99fd1565b8fc37f2524f` and preserved Intel DMG `6aaf2af3432f29382c45277ab41cb7ceb69a994363494bbb8eed54e7a82edda6` inventoried 236 and 234 Mach-O files respectively. On each package's selected architecture, 103 delivered files have exact section-payload matches to 56 preserved SDK library/plugin inputs, covering 28 named SDK components. Within `MWNet.app`, 55 of 170 Apple Silicon files and 55 of 169 Intel files match these SDK payloads. Other files include the runtime's own executables, Qt and Homebrew providers; an unmatched file is not by itself a failure. The [receipt](2026-11-05-macos-sdk-payload-mapping.json) records per-provider hashes, package paths, ownership and SPDX version records. Both complete SDK archives were checked against their existing SHA256 pins before extraction.

These are section-payload matches, not whole-file byte identities. The comparison includes architecture, header flags, file-backed section bytes and metadata, zero-fill metadata and relocation bytes. It excludes loader commands, LINKEDIT symbol/export tables, signatures and padding. None of the 103 matched files per architecture is whole-file byte-identical to its SDK input; the receipt retains both whole-file hashes. Loader library names, versions and minimum OS metadata are inventoried separately. This provides scoped provider evidence after bundling changes while leaving full binary equivalence, source/notice completeness and runtime acceptance separate.

The delivered bundles contain two distinct FreeType and libpng providers. Each architecture's versioned `libfreetype.6.20.2.dylib` matches the SDK's FreeType 2.13.3 sections, while the separate `libfreetype.6.dylib` does not. Likewise, `libpng16.16.54.0.dylib` matches the SDK and `libpng16.16.dylib` requires separate provider mapping. Apple Silicon also delivers SDK brotli 1.2.0 payloads alongside a separate `libbrotlidec.1.2.1.dylib`. The captured Homebrew dependency list cannot be substituted for all delivered provider bytes. These distinctions remain part of the source/notice preparation.

Both actual images contain selected-architecture libraries declaring a minimum macOS deployment target of 15.0.0; in the preserved Intel image this includes `libcrypto.3.dylib`. The highest observed minimum target on either selected architecture is 15.0.0. This is static deployment metadata, not execution on every OS version. Native package/startup checks remain limited to the recorded macOS 15 hosts, and older macOS compatibility is not established. No target was lowered, image rebuilt or package resigned during this inspection.

Two earlier local analysis attempts remain failed and preserved for each architecture. The first selected SDK alias symlink chains that 7z refused to materialize; the corrected procedure selects only regular library/plugin entries. The second stopped at a valid Abseil empty compatibility library, `libabsl_source_location.2608.0.0.dylib`; the corrected parser inventories its loader metadata but gives it no comparable section fingerprint, preventing empty payloads from being accepted as provider matches. Original failed receipts, extracted material and the two exact prior tool sources remain under the private staging root. These local tooling outcomes are distinct from the earlier failed Intel DMG packaging job and its separate successful preserved-image validation.

Seven offline regressions passed for loader-versus-section changes, malformed/truncated regions, zero-fill metadata, empty libraries, relocation changes, universal architecture binding and SDK alias-chain selection. The final inspection read all selected package binaries and retained detailed reports under `macos-arm64-sdk-section-inspection-v3/` and `macos-intel-sdk-section-inspection-v3/` within `build/platform-stable-1.0.0-a6868387dc/`. No new native CI or graphical run was dispatched. Complete dependency/source/notice assembly and native graphical gameplay remain open, the platforms remain experimental, and published Linux assets and NUC production are unchanged.

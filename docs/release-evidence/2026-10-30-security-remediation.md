# Focused security remediation checkpoint

This checkpoint corrects three availability/input-validation findings identified during the maintainer-authorized ECC AI review of published alpha.3 source `d871d54894a0774db7dbcaedc3a0955bacbc08b3`. The starting checkout was `6d35f2ddd16841385e1759f45e892d2b07b3e629`; tests below exercised the actual corrective source files in the working tree, not a clean release candidate. No public service or private account data was used.

- Authentication requests rejected by the per-address pre-KDF bucket no longer allocate account/address failure records. A regression with four tracking slots proves rejected rotating names cannot consume the remaining slots, another address can begin an attempt and refill still works. It failed on the original code and passes after correction.
- The server checks client content-manifest shape before accessing the first checksum. Client entries require nonempty filenames and exactly one checksum, including valid CRC zero. Server requirements retain zero/multiple-checksum semantics in the shared codec. Actual packet round trips cover those distinct roles.
- Discovery JSON is structurally limited before PropertyTree allocation. The new 4,096-unit budget preserves quoted punctuation and 100-envelope pages, rejects the broad-array regression and leaves signature bytes and wire labels unchanged. The new rejection test fails against the original parser. A fixed two-MiB fixture used about 15.6 MiB peak RSS versus about 320.5 MiB before correction in the local native measurement.

Using the existing Ubuntu/Clang builder image `sha256:abbdee8b62e728bcb70828b84e0dff05c01a5c174667076e3af5d20e5c5a47fc`, all six native suites passed after rebuilding the server and eight relevant targets: headless transport, native security/mechanics, actor packets, magic content, persistence fault injection and discovery. Total CTest wall time was 18.15 seconds. A copied ASan/UBSan security/mechanics and persistence build passed both suites in 8.56 seconds with leak detection enabled. The directory review separately checked its structural fixture under ASan/UBSan, local HTTPS negative cases and 37 operator/deployment tests. Full GUI/GNS/all-component instrumentation is not claimed.

Private local diagnostics and fail-before/pass-after evidence are retained under `build/ecc-review/`; historical release binaries, logs and the completed eight-hour receipt were preserved. These changes affect runtime allocation/authentication, so corrected-candidate rendered/package and sustained-operation acceptance must be refreshed before stable publication. This checkpoint neither patches existing downloads/NUC services nor promotes a release.

# September 18 graphical gameplay test: blocked

The combined Linux preview at runtime commit
`56fcea73f4b4ec0d23a8ebc93ea40da55e206d40` was tested on the local desktop.
Archive SHA-256:
`b39c100c179fe1082ba92618ea37dd2b135f1c4335f8912228ec382e703c1603`.

The Ubuntu runtime used the host GPU, X11 authorization and audio socket.
Morrowind, Tribunal and Bloodmoon content was mounted read-only. Test accounts,
profiles, trust and world state were isolated under
`build/gameplay-56fcea73f4/`; existing player saves/server state were not reused.
Generated account credentials are private test artifacts and are not included
in this record or in the release archive.

## Results

- The original local launcher exited before rendering: its forced direct-connect
  invocation supplied no protocol-11 account password. Explicit test credentials
  and the independently observed local server fingerprint allowed authentication.
- This installation also required explicit content and BSA archive selection.
  Adding those arguments to the diagnostic launcher eliminated missing-image
  errors. The packaged launcher itself remains unchanged and needs repair.
- The server loaded real canonical game content; the client initialized AMD GPU
  rendering and audio, authenticated, and began loading the world. A 1280x720
  OpenMW-titled game window was confirmed on the desktop.
- The session then disconnected with `authenticated message verification failed`.
  GDB on the unchanged client stopped at `SecureSession.cpp:186`, where a receive
  counter mismatch sets `SecurityError::ReplayDetected`. The stack continued
  through `SecureTransport::Impl::acceptSecureData`, `rawMessage`, `process` and
  `poll`. This happened during ordinary authenticated gameplay startup.
- The strict global receive counter and transport lanes warrant investigation;
  cross-lane reordering is a hypothesis, not a verified root cause. No encryption
  or replay protection was weakened to get past the error.
- The first attempt, which lacked archive settings, subsequently crashed with
  exit 139 during shutdown. Its exact cause was not established. The attempt
  with corrected archives remained running after disconnect; that observation
  does not prove the crash is repaired.
- An intervening reconnect authenticated but logged an unreadable saved player
  JSON record followed by transport shutdown. Persistence/restore needs its own
  investigation; a credential failure is not inferred from this log.

This is **not playable-gameplay acceptance**. Startup/version checks and the
previous headless soak did not exercise this complete CoreScripts/graphics path.
The recorded preview evidence must not be interpreted as clearing these issues.
No runtime fixes, replacement release archive or new soak were produced by this
bounded gameplay investigation.
